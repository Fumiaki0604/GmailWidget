# GmailWidget 実装計画書

## 概要

Gmail重要メール常駐ウィジェットを **Electron** でデスクトップアプリ化する。
プロトタイプ（`prototype/index.html`）のUI資産を活用し、4フェーズで段階的に実装する。

### 担当凡例

| 記号 | 担当者 | 説明 |
|------|--------|------|
| 👤 | 人間 | 外部サービス設定、手動確認、アカウント操作など |
| 🤖 | AI (Claude Code) | コーディング、ファイル生成、テスト実行など |
| 👤+🤖 | 共同 | AIが実行し、人間が確認・承認する作業 |

### 技術スタック

| 層 | 技術 |
|----|------|
| デスクトップフレーム | Electron 33+ |
| レンダラー | HTML/CSS/JS（プロトタイプ流用） |
| メインプロセス | Node.js (TypeScript) |
| Gmail API | googleapis npm package |
| AI判定 | @anthropic-ai/sdk (Claude Haiku) |
| 設定永続化 | electron-store |
| パッケージング | electron-builder |

### アーキテクチャ概要

```
Electron
├── Main Process (Node.js)
│   ├── Gmail APIポーリング（5分間隔）
│   ├── ルールベースフィルタ
│   ├── Claude Haiku APIスコアリング
│   ├── electron-store（設定・認証トークン保存）
│   ├── システムトレイ管理
│   └── IPC Bridge → Renderer
└── Renderer Process (HTML/CSS/JS)
    └── prototype/index.html を Electron向けに改修
```

#### OAuth2フロー詳細（デスクトップアプリ方式）

```
1. ElectronがランダムポートでローカルHTTPサーバーを起動
2. Google認証URLをデフォルトブラウザで開く
3. ユーザーがブラウザでGoogleログイン・権限許可
4. Googleがlocalhostにリダイレクト（認証コード付き）
5. ローカルサーバーが認証コードを受け取る
6. 認証コードでアクセストークン・リフレッシュトークンを取得
7. electron-storeにトークンを暗号化保存
8. ローカルHTTPサーバーを終了
```


## 実装上の注意事項

### セキュリティ

| 項目 | 対応 |
|------|------|
| APIキー管理 | `.env` + `electron-store`（暗号化）、Gitに含めない |
| レンダラーからのNode.js直接アクセス | `contextIsolation: true` + `preload.ts` 経由のみ |
| 外部URLの開き方 | `shell.openExternal()` を使用、`webContents.loadURL()` は禁止 |
| `credentials.json` | `.gitignore` 必須 |

### コスト管理（Claude Haiku）

```
想定コスト:
- 1日あたりのルールフィルタ通過: 5〜20件
- Haiku: 入力 $0.25/MTok、出力 $1.25/MTok
- 1件あたり: 件名(~50トークン) + レスポンス(~30トークン)
- 月額見込み: 20件/日 × 30日 × 80トークン = 48,000トークン → 約¥1〜2
```

### Electron セキュリティ設定

```typescript
// main.ts
new BrowserWindow({
  webPreferences: {
    contextIsolation: true,      // 必須
    nodeIntegration: false,      // 必須（レンダラーでNode.js禁止）
    preload: path.join(__dirname, 'preload.js')  // IPC経由のみ
  }
})
```
